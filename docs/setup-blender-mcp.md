# Blender и MCP: подготовка на новом компьютере

Этот пакет не меняет настройки компьютера при распаковке. Агент сначала проверяет установленный Blender, FFmpeg и доступные инструменты, затем выбирает живое подключение или фоновый рендер. Для примеров нужен Blender 5.2+; точная версия, на которой пакет проверен, записана в README и отчёте проверки.

## 1. Проверка без установки

Из корня распакованной папки:

```powershell
python scripts/doctor.py --json
```

Если Blender установлен вне PATH, передайте его путь:

```powershell
python scripts/doctor.py --blender "C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" --json
```

Путь выше - пример, не обязательная папка. На macOS и Linux используйте свой исполняемый файл. Можно задать `BLENDER_PATH`. `doctor.py` показывает только наличие ключа ElevenLabs, никогда его значение. По умолчанию сетевых запросов нет. Поля `ready_for_stills`, `ready_for_video` и `ready_for_export_verification` разделяют готовность PNG-рендера, кодирования видео и проверки метаданных: отсутствие FFmpeg не блокирует картинки.

## 2. Если Blender MCP уже подключён

Попросите агента найти инструменты подключённого Blender: прочитать версию и состав сцены, затем получить изображение камеры/viewport. Названия инструментов зависят от реализации MCP; не подставляйте выдуманные методы. Например, подключение из исходного проекта предоставляло `get_addon_status`, `get_scene_info`, `execute_blender_code`, `look`.

Перед изменениями сохраните отдельную копию текущей сцены. Работайте со своей коллекцией и своими объектами. Чужой открытый проект не сбрасывайте. Большой рендер запускайте из сохранённой копии фоновым процессом, а не длинным блокирующим вызовом к интерфейсу.

Не устанавливайте второй мост поверх исправного первого только ради совпадения названия. Доступный TCP-порт ещё не доказывает работоспособность MCP: нужно получить реальный ответ инструмента и изображение.

## 3. Если подключения ещё нет

У сообщества есть [MCP for Blender](https://github.com/ahujasid/mcp-for-blender). Это сторонний проект, не продукт Blender Foundation. Старое имя `blender-mcp` заменено на `mcp-for-blender`; для новой установки следуйте текущему README автора.

Понадобятся Blender, Python и `uv`/`uvx`. Проверяйте актуальные требования в README. Установка и настройка моста - отдельный явный шаг, а не скрытое действие при запуске примера.

Минимальный маршрут из документации проекта:

```text
uvx mcp-for-blender install-addon
codex mcp add blender -- uvx mcp-for-blender
codex mcp list
```

В Blender включите установленное дополнение MCP for Blender в Preferences / Add-ons. Проверьте его состояние в боковой панели 3D View. Если сервер не запущен, запустите его там. После настройки перезапустите клиент агента, чтобы появились инструменты.

Если GUI-клиент не видит `uvx`, найдите полный путь через `where.exe uvx` в Windows или `command -v uvx` в macOS/Linux и используйте этот путь в настройке сервера. При конфликте Python README автора предлагает запуск через управляемый Python 3.11.

Для Codex используйте интерфейс MCP вашего установленного клиента либо команду выше. Официальная документация описывает также пользовательский и проектный `config.toml`; не заменяйте весь существующий конфиг шаблоном из интернета. [Документация Codex MCP](https://developers.openai.com/codex/mcp/).

После установки проверьте три вещи: инструмент возвращает версию Blender, видит тестовую сцену и показывает её изображение. При сбое зафиксируйте ошибку и переходите к фоновому режиму, если задача не требует интерактивного редактирования. Не застревайте на MCP, когда локальный Blender уже может отрендерить проект.

## 4. Фоновый режим работает без MCP

Из корня пакета:

```text
python scripts/render_example.py --mode stills --output output/examples
python scripts/render_example.py --mode camera --output output/camera --encode
python scripts/render_example.py --mode animation --output output/animation --encode
```

При необходимости добавьте `--blender "полный/путь/к/blender"`. Для быстрой пробы есть `--percent 50`; финальную проверку делайте в полном размере. Исполняемые примеры запускают Blender в фоне. Они не должны открывать дополнительные окна на компьютере пользователя.

`camera` проверяет движение камеры; `animation` - отдельный пример движения. Ни один короткий пример не заменяет производство нового фильма по брифу. Если `--encode` используется, нужны `ffmpeg` и `ffprobe`.

## Что агент делает после подключения

1. Читает выбранный бриф и активный скилл из `skills/`.
2. Делает пять настоящих тестовых рендеров: позы, предметные контакты, два персонажа, интерьер, ключевой крупный план.
3. Открывает изображения, исправляет видимые дефекты, затем делает короткую проверку движения.
4. Сохраняет `.blend`, исходники, настройки рендера и отчёт. Не выдаёт сгенерированную картинку за рендер Blender.

Источники настройки проверены 04.11.2026: [README MCP for Blender](https://github.com/ahujasid/mcp-for-blender), [официальная документация Codex MCP](https://developers.openai.com/codex/mcp/). Перед установкой на другой версии клиента сверяйте актуальные страницы.
