# Озвучка, SFX и сведение

Звук объясняет действие: дверь закрывается вместе с движением створок, мотор меняет режим при остановке, выключатель щёлкает в момент отключения. Не ставьте один громкий whoosh на каждый монтажный стык.

## Озвучка

Сначала выберите персонажей и голоса в брифе. Для каждого нового голоса сделайте короткую пробу с настоящей репликой: оцените тембр, произношение, эмоцию и громкость. Не ускоряйте и не понижайте голос до неприятного звучания только ради отличия персонажей. Солнцу, роботу или животному тоже нужен разборчивый, приятный голос.

Одна реплика/смысловой блок - один UTF-8 файл. В файл TTS включайте только произносимый текст, без названия персонажа, таймкодов и режиссёрских ремарок.

Скрипт использует официальный [Text to Speech with timestamps](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps). Ему нужны ваш `voice_id`, выбранная модель и локальная переменная `ELEVENLABS_API_KEY`.

Проверка без сети и без чтения ключа:

```text
python scripts/elevenlabs_voice.py --voice-id YOUR_VOICE_ID --text-file output/voice/line-01.txt --output output/voice/line-01.mp3 --dry-run
```

Реальная генерация той же реплики:

```text
python scripts/elevenlabs_voice.py --voice-id YOUR_VOICE_ID --model eleven_multilingual_v2 --text-file output/voice/line-01.txt --output output/voice/line-01.mp3
```

`YOUR_VOICE_ID` - заменяемый идентификатор голоса, не ключ. В качестве воспроизводимого базового выбора используется `eleven_multilingual_v2`, документированная модель по умолчанию этого endpoint; агент может выбрать другую доступную модель по брифу и текущему API. Доступ к голосу и модели зависит от аккаунта. Скрипт не обещает определённую цену или лимит.

Результат: MP3 и соседний `.alignment.json` с исходным/нормализованным выравниванием и списком слов. При нормализации числа или сокращения могут отличаться от исходной записи; сопоставьте субтитры с тем, что реально произнесено. Для нескольких персонажей генерируйте отдельные клипы, затем добавляйте смещение начала каждого клипа к его временным меткам.

Если пользователь прислал готовую озвучку и точный текст, не генерируйте её заново. Для выравнивания есть официальный [Forced Alignment](https://elevenlabs.io/docs/api-reference/forced-alignment/create): multipart-запрос с аудиофайлом и текстом, ответ со словами и временами. Этот метод не выполняет разделение говорящих. В пакете поставляется CLI генерации TTS, а не готовый клиент Forced Alignment; при таком маршруте агент реализует или использует доступный клиент по актуальной документации.

## Субтитры

При выбранном пословном режиме один экранный элемент соответствует одному произнесённому слову. Не вычисляйте времена простым делением длины фразы. Исправляйте ошибки распознавания по аудио, не удаляя неудобные слова. Белый текст с тёмной обводкой/тенью проверяйте и на светлом, и на тёмном фоне. Положение и размер зависят от формата и выбранного режима; не перекрывайте рот, кисти или важный предмет.

Для обычного мультфильма режим субтитров выбирается в брифе. Пословные пиксельные подписи из старых Reels не становятся обязательными для любого горизонтального фильма.

### Нативные субтитры в Blender

В `studio/captions.py` есть готовый helper для плоских фронтальных сцен. Он принимает `.alignment.json` из ElevenLabs CLI либо список `text/start/end`, создаёт редактируемые белые FONT-объекты, чёрную расширенную копию для контура и покадровую видимость.

```python
from captions import add_captions
add_captions(scene, "voice.alignment.json", x=960, y=710, size=96,
             mode="word", outline_width=2.5)
# Фразы: mode="phrase", max_words=4
```

Координаты задаются в единицах холста: для примеров это 1920×1080. По умолчанию `pin_to_camera=True`: текст закреплён на ортографической камере и сохраняет экранное положение и размер при её движении и зуме. Для текста внутри самой сцены передайте `pin_to_camera=False`. Это helper для плоской фронтальной постановки; для перспективной 3D-сцены нужен свой overlay-проход.

`examples/captions/` содержит настоящие тестовые PNG и .blend, включая проверку после движения камеры и зума. `templates/caption-fixture.alignment.json` - явно искусственные учебные времена, не результат распознавания речи. Их нельзя использовать как синхронизацию нового фильма.

## Библиотека звуков

Смотрите `assets/sfx/` и её `sources.json`. В исходной библиотеке есть записи дверей лифта, готовый сигнал, выбранные UI-звуки Kenney и отдельно созданный процедурный гул, спад питания, металлический скрип и тревожный фон. Синтезированный эффект не называйте полевой записью. Источник, автор, лицензия и изменения сохраняются рядом с файлом.

Примеры сборки события:

| Событие | Слои и момент |
| --- | --- |
| Лифт | короткий щелчок кнопки; механика дверей по их движению; тихий мотор во время хода; сигнал перед открытием |
| Отключение света | выключатель/реле; затухающий электрический гул; затем пауза и более тихая атмосфера комнаты |
| Напряжение | негромкий низкий фон; отдельный скрип в видимом источнике; короткая тишина перед важным действием |
| Предмет появился | короткий мягкий акцент, если он помогает заметить появление; не обязательный звук для каждого объекта |
| Шаги | опорная фаза стопы/лапы, подходящий материал пола; отдельный ритм человека, собаки и робота |

«Звук темноты» - условная атмосфера после исчезновения знакомых шумов, а не непрерывный громкий гул. Сохраняйте пространство для голоса и пауз.

## Сведение и проверка

1. Сначала сведите реплики к сопоставимой воспринимаемой громкости. Слушайте начало и конец каждого клипа: не обрезаны ли согласные/дыхание.
2. Добавьте тихую атмосферу и синхронный Foley. На время речи ослабляйте музыку и маскирующие эффекты.
3. Уберите клиппинг и резкие стыки; короткие фейды не должны съедать смысловые атаки вроде щелчка кнопки.
4. Слушайте в наушниках и на обычном динамике. Числовой отчёт сам по себе не доказывает приятный голос или хороший SFX.
5. Измерьте итоговый пик и громкость доступным аудиоанализатором/FFmpeg. Рабочий ориентир для демонстрационного файла - около -14 LUFS и true peak не выше -1 dBTP; это настройка проекта, не обязательное правило всех платформ.

В отчёте отделяйте: файл создан; параметры измерены; звук действительно прослушан. Не отмечайте прослушивание, если инструменты позволили только увидеть waveform или значения пиков.
